# mutation_report.md — PBH-VERIFY-01

## 0. Предрегистрация (записано 2026-09-28 до появления кода и тестов)

Цель: измерить чувствительность проверок (разработческих тестов, независимой матрицы, аудита) к контролируемым дефектам. Основной код и контракт не меняются; каждый мутант — отдельная копия `mutants/<id>/src/sphdiag`, порождаемая скриптом-патчем `mutants/make_mutants.py`.

Классы дефектов (минимальный набор ТЗ §9 + дополнительные):

| id | Класс | Намерение (реализация уточняется по коду после его появления) |
|---|---|---|
| M1 | ареальный ↔ координатный радиус | в M_MS и/или θ± использовать r вместо R |
| M2a | знак K_ij | U = +R K_B вместо −R K_B |
| M2b | ориентация нормали | s^a → −s^a (Γ = −R′/A) |
| M3a | потерян 4π | M_flux без 4π (или 𝓗_M без 4π в потоковом члене) |
| M3b | 8π/16π | 𝓗 с 8πρ вместо 16πρ |
| M3c | коэффициент потенциала | V = m²φ² вместо ½m²φ² |
| M4a | знак потока | j_r = +Πφ′ |
| M4b | поток исключён | U j_r → 0 в 𝓗_M и M_int |
| M5 | космологическая marginal-сфера объявлена PBH | `ah_candidate` без требования θ₋ < 0 / внутренней trapped-стороны |
| M6 | ожидаемый ответ теста зависит от проверяемой реализации | мутант **теста**: эталон вычисляется функцией модуля (проверяется, заметит ли аудит) |
| M7 | NaN трактуется как отсутствие коллапса | нечисловые Rθ± отбрасываются, статус → `NO_TRAPPED_SPHERES` |
| M8 | чётность в центре | R продолжается чётно |
| M9 | порядок производных | 2-й порядок вместо 4-го |
| M10 | Γ через γ_rr | Γ = R′/A² |

Для каждого мутанта фиксируется: внесён ли; физически ли нетривиален; эквивалентен ли (не меняет вывод ни на каких данных); ломает ли синтаксис/импорт немедленно; каким тестом обнаружен (разработческие тесты / независимая матрица / аудит); до или после ручной проверки; до или после усиления тестов.

Отдельно: в копию кода, передаваемую агенту adversarial audit, **тайно** вносится 3–4 дефекта из этого списка (аудитор об этом не знает). Результаты аудита по ним — мера чувствительности аудита; находки вне этих дефектов — естественные ошибки основного кода.

Сразу оговорка: ~10 искусственных дефектов не дают оценки вероятности правильности модуля; это проверка чувствительности конкретных тестов к конкретным классам ошибок.
