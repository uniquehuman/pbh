## Подробно

### A1 — critical — неверная чётность R при вычислении R′ (diagnose.py:404–405)

**Что не так.** `dR, sig_dR = op.d_err(R, R, +1)` и `dR6 = op.d(R, +1, 6)`: призрачные точки строятся как R(−r) = +R(r). Контракт §3/§8 и README пакета: R — **нечётная**. Правильно: parity −1. Для остальных полей чётности верны (Γ, R′, K_B, φ — +1; M, Γ′ — −1).

**Сценарий / вывод пробы** (`audit_work/p1_parity_R.py`, плоское пространство R = r, A = 1, K = 0):
```
vertex Gamma[:4] = [0. 1.166667 1. 1.]   (точно: 1)
vertex status {'data': 'NUMERICAL_FAILURE', ..., 'geometry': 'UNDETERMINED'}  failures ['M_over_R3']
cell   Gamma[:4] = [0.583333 1.083333 1. 1.]; M[:2] = [0.008247 -0.00651] (точно 0)
cell   status {'data': 'OK', 'constraints': 'CONSISTENT_WITH_TRUNCATION', 'geometry': 'NO_TRAPPED_SPHERES'}; Gamma0 (экстраполяция) = 0.495
```
`audit_work/p8_cell_silent.py` (общий срез с потоком, `cell`, N = 50…400): ошибка Γ в первой точке 0.417 **не убывает** с N; 2M/R в первой точке 0.66 при точном 7·10⁻⁴…10⁻⁵; во второй точке 2M/R = −0.17 (отрицательная масса) — без какого-либо флага.
Последствия: (i) при `vertex` любой срез с численной R′ получает `UNDETERMINED` (модуль фактически неработоспособен для регулярного центра); (ii) при `cell` — тихо неверные Γ, M, 2M/R, Rθ± в центральной области, где при коллапсе ПЧД и происходит главное.

**Исправление.** `op.d_err(R, R, -1)`, `op.d(R, -1, 6)`. Проверено на копии `audit_work/patched`: Γ = 1, M = 0 до округления, все тесты центра проходят.

**Как найдено.** Сначала чтением (сравнение строки 404 с таблицей чётностей README/контракта §3), затем собственными пробами p1, p8; подтверждено падением 16 тестов разработчика (`test_minkowski_*`, `test_flrw[*]`, `test_closed_flrw_*`, `test_center_*`, `test_generic_slice_convergence[*]`, `test_sigma_bounds_*`, …).

### A2 — critical — ложный AH-кандидат: сфера Хаббла / космологическая marginal-сфера (diagnose.py:318–319)

**Что не так.** `ah = bool(rtype != DEGENERATE and G_star > 0 and inner == -1 and outer == 1)`. Контракт §7: кандидат **только** если нуль у θ₊ и θ₋ < 0 (FUTURE_MOTS). Код пропускает корни θ₋ типа PAST_MOTS. Для корня θ₋ при Γ > 0 всегда θ₊ = 4Γ/R > 0 (PAST_MOTS); «− внутри / + снаружи» — это ровно граница normal → past-trapped, т.е. космологический (Хаббловский) горизонт расширяющейся Вселенной.

**Сценарий / вывод пробы** (`audit_work/p3_hubble_sphere.py`, `p9_misc.py`, `center="none"` — независимо от A1):
```
плоский FLRW, H = 1.5: {'which': '-', 'R': 0.6667, 'type': 'PAST_MOTS', 'ah_candidate': True} → status AH_CANDIDATE
замкнутый FLRW, H = 1.5: корень θ₋ PAST_MOTS, ah_candidate True → AH_CANDIDATE
синтетический срез «ЧД при r = 1 + Хаббловская сфера при r = 3»:
   outer_ah_candidate → r = 3.0, which '-', type PAST_MOTS   (настоящий AH r = 1 вытеснен)
```
То есть любой срез ПЧД в расширяющемся FLRW, захватывающий Хаббловский радиус, получает `AH_CANDIDATE` ещё до коллапса, а `outer_ah_candidate` (R, M горизонта) указывает на Хаббловскую сферу: масса «ЧД» = M_MS(1/H) ≈ масса горизонта. Это ровно та ложная интерпретация, которую контракт запрещает («PAST_MOTS … никогда не PBH»).

**Исправление.** `ah = bool(which == "+" and rtype == FUTURE_MOTS and G_star > 0 and inner == -1 and outer == 1)` (с учётом A6 — см. ниже). На `audit_work/patched`: FLRW → `PAST_TRAPPED_ONLY`, синтетический срез → `outer_ah_candidate` r = 1.0, '+', FUTURE_MOTS.

**Как найдено.** Чтением (сопоставление с контрактом §7 и с замечанием derivation.md D8 «условие Γ>0 избыточно» — код опирается только на него), затем пробы p3, p9; подтверждено падением `test_past_trapped_only_and_marginal_edge` и `test_flrw[1.5-*]` (последние падают также из-за A1).

### A3 — critical — потенциал без множителя ½ (matter.py:72)

**Что не так.** `potential()` возвращает `m_phi**2 * phi**2`; контракт §1: V = ½m²φ² (докстринг класса тоже говорит «/2»). Ошибка входит в ρ [F3], S^r_r, S^θ_θ [F5] и, следовательно, в 𝓗, 𝓗_M, M_ρ, M_int, M_prop.

**Сценарий** (`audit_work/p2_potential.py`, однородное поле φ = 0.2, Π = 0, m = 2):
```
rho = 0.16   (ожидается V = 0.08)
согласованный срез ФКГ (H² = 8πV/3): constraints = VIOLATED, ham_rel = 0.333
срез, построенный с неверным V = m²φ²: constraints = CONSISTENT_WITH_TRUNCATION (ham_rel 1e-13)
```
Правильные данные EKG бракуются, неправильные принимаются. Для осциллирующего поля (главный сценарий брифа, m_φ ≫ H) ρ и давление искажены в фазе потенциального преобладания: ⟨p⟩ по периоду уже не 0.

**Исправление.** `return 0.5 * self.m_phi ** 2 * self.phi ** 2`.

**Как найдено.** Чтением (сравнение с докстрингом и §1), затем проба p2; подтверждено падением `test_scalar_field_projections_formulae_and_order`, `test_fkg_homogeneous_scalar_slice` (по проверке S_rr), `test_scalar_field_time_symmetric_star_converges`.

### A4 — major — знак потоковой массы (diagnose.py:521)

**Что не так.** `M_flux = op.cumint(-FOUR_PI * R**2 * U * j_r, +1)`; контракт §6 и F10: M_flux = +∫4πR²U j_r dr (сама невязка 𝓗_M на стр. 487 записана верно, с «−4πR²U j_r» в 𝓗_M = M′ − …). Итог: M_int = M(r₀) + M_ρ − ∫4πR²U j_r ≠ M_MS.

**Сценарий** (`audit_work/p4_mflux.py`, общий срез с потоком, ρ и j_r из 𝓗 = 𝓜 = 0, `center="none"`):
```
N=100/200/400: status CONSISTENT_WITH_TRUNCATION | max|M_int − M| = 1.057e-01 (не сходится)
M_flux[-1] = +0.05284, trapz(+4πR²U j_r) = −0.05284; M(r0)+M_rho−M_flux совпадает с M до 2e-7…1e-9
```
Масса, приписываемая радиальному потоку (важна для скалярного поля, у которого на любом не-φ=const срезе j_r ≠ 0), имеет неверный знак; расхождение M_int с M_MS никак не отражено в статусах (см. A12).

**Исправление.** Убрать знак минус. Проверено на `audit_work/patched` (max|M_int − M| = 2·10⁻⁷ → 1.4·10⁻⁹).

**Как найдено.** Чтением (сопоставление стр. 521 со стр. 487 и контрактом §6), затем проба p4; подтверждено падением `test_M_flux_matches_milligan_form` и проверки порядка M_int в `test_generic_slice_convergence`.

### A6 — major (контракт §7 + код) — критерий AH зависит от ориентации метки r; область Γ < 0 не покрыта

**Что не так.** Контракт §2: r — «любая монотонная метка сфер»; s^a — в сторону роста **r**. Критерий кандидата (§7) привязан к θ₊ и к «внутри/снаружи» по r и дополнительно требует Γ > 0. При перенумерации r → C − r (R убывает по r) горизонт того же пространства-времени становится корнем θ₋ с Γ < 0, trapped-область — «снаружи» по r, и кандидат пропадает. Физически инвариантное определение: «исходящее» (в сторону роста R) расширение θ_out = θ₊ при Γ > 0 и θ₋ при Γ < 0; кандидат — нуль θ_out, другое < 0, θ_out < 0 со стороны меньших R и > 0 со стороны больших R.

**Сценарий** (`audit_work/p5_orientation.py`, Шварцшильд PG, M = 1; та же картина на `patched`):
```
возрастающая метка : AH_CANDIDATE  [('+', R=2.0, FUTURE_MOTS, True)]
убывающая метка    : FUTURE_TRAPPED_NO_AH_CANDIDATE  [('-', R=2.0, FUTURE_MOTS, False, inner '+', outer '-')]
```
Для ПЧД с регулярным центром R растёт от центра, так что в обычной конфигурации проблема не проявляется; но для данных типа II (немонотонный R, горловина; derivation.md §7 п. 6) горизонт за горловиной не будет отмечен. Статус при этом не доброкачественный (`FUTURE_TRAPPED_NO_AH_CANDIDATE`), поэтому major, а не critical.

**Исправление.** В контракте: определить кандидат через θ_out и ориентацию по R (см. выше); в коде: `which_out = '+' if G_star > 0 else '-'`, условие на знаки — в направлении роста R (inner/outer поменять местами при Γ < 0); как минимум — warning, если есть FUTURE_TRAPPED и Γ < 0 где-либо на срезе.
**Как найдено.** Чтением контракта (§2 vs §7), затем проба p5.

### A7 — major (контракт §9 + код) — оценка ошибки скрывает ошибки, которые сама же порождает

**Что не так.** σ(f′) = |D⁴f − D⁶f| (fd.py:136–148) — эвристика для гладких разрешённых данных. На изломе / неверном продолжении через центр / скачке обе производные ошибочны на O(1) и различаются на O(1); порог κ_c·σ (κ_c = 10, diagnose.py:506) поглощает невязку. Статус называется `CONSISTENT_WITH_TRUNCATION`, хотя данные не согласованы и не сходятся.

**Сценарии.**
- A1 при `cell` (p1): Γ(r₀) = 0.58 вместо 1, M < 0, статус `OK / CONSISTENT_WITH_TRUNCATION / NO_TRAPPED_SPHERES`.
- p9: R = |x − 1| (два шара, склеенные центрами, излом Γ = −1 → +1) при вакууме — `OK / CONSISTENT_WITH_TRUNCATION`.
- Для сравнения (что работает): тонкая оболочка без материи (p10) обнаруживается, но с запасом лишь |𝓗|/(κ_c σ) ≈ 1.8, независимо от массы оболочки и N; гладкое нарушение ρ·(1+10⁻³) ловится уже при N = 40 (p7).

**Исправление.** (а) Статус `UNRESOLVED` / warning там, где σ(X) сравнима с Σ|T_k| (например σ/Σ|T_k| > 0.1) — данные не разрешены, и «согласие» ничего не значит; (б) в документации §9: `CONSISTENT_WITH_TRUNCATION` не означает согласованности на негладких данных, проверка — только сходимостью на двух сетках; (в) предпочтительно — встроенный режим двух разрешений (прореживание ×2) с проверкой порядка сходимости.
**Как найдено.** Пробами (p1, p8 при исследовании A1; затем целенаправленно p9, p10, p7).

### A8 — minor — проверки центра не влияют на статус (diagnose.py:554–565)

Контракт §3: модуль «проверяет … и сообщает отклонения». Код кладёт Γ(0), K_A(0) − K_B(0) в `center_checks`, но не добавляет warning и не меняет статус. При A1/`cell` `Gamma0 = 0.495` (p1) — статус `OK`. **Исправление:** warning и (при |Γ(0) − 1| > κ·σ_Γ0 + tol) статус данных `CENTER_IRREGULAR` или хотя бы `status['warnings']`. **Как найдено:** чтением, подтверждено p1.

### A9 — minor — R = 0 вне регулярного центра молча принимается (slice.py:130–150; diagnose.py:441, 461–467)

Валидатор отвергает только R < 0 и R[0] ≠ 0 для `vertex`. R = 0 во внутренней точке или при `center="none"` получает класс `CENTER`, θ± = NaN «документированно», к M/R³ применяется предел регулярного центра (формула с Γ = 1). Проба p9: R = |x − 1| → `OK / CONSISTENT_WITH_TRUNCATION / NO_TRAPPED_SPHERES`, warnings = [], errors = []. Для эволюционных данных R → 0 вне центра — признак сингулярности или краха координат, а не «центр». **Исправление:** R = 0 допустимо только в r[0] при `center="vertex"`; иначе `INVALID_INPUT` (или UNDETERMINED с ошибкой). **Как найдено:** чтением slice.py, затем проба p9.

### A10 — minor (контракт §7) — неразрешённый знак трактуется как «past-trapped»

Точки (+,0) при Rθ₋ → 0⁻ (далёкая зона гиперболоидального среза Минковского, derivation.md §7 п. 5) становятся `PAST_MARGINAL`; по контракту `PAST_MARGINAL` без trapped-точек даёт `PAST_TRAPPED_ONLY`. Проба p6: плоский гиперболоид τ = 1, r ∈ [0.5, 10⁷], N = 200 (геометрическая сетка) → 23 точки `PAST_MARGINAL`, статус `PAST_TRAPPED_ONLY` (|Rθ₋| = 5·10⁻⁸ < τ = 4·10⁻⁶). До r/τ = 10⁵ всё корректно (`NO_TRAPPED_SPHERES`). Асимметрия: будущая сторона в той же ситуации даёт `UNCERTAIN`. **Исправление (контракт):** `PAST_MARGINAL`, не отнесённые к корню PAST_MOTS с разрешёнными сторонами, → `UNCERTAIN` (или `NO_TRAPPED_SPHERES` с `marginal_present`), но не `PAST_TRAPPED_ONLY`. **Как найдено:** пробой по открытому вопросу derivation.md §7 п. 5.

### A11 — minor — ложный VIOLATED на недоразрешённом крае

Проба p6/p6b: точный Минковский-гиперболоид на равномерной сетке r ∈ [0.5, 10⁵], N = 2000 (h = 50 при масштабе кривизны ~1 у внутреннего края) → `constraints = VIOLATED` (1 точка 𝓗 в r₀: |𝓗| = 4.7, σ = 0.039). σ = |D⁴ − D⁶| не оценивает ошибку одностороннего шаблона на недоразрешённом участке. Сторона безопасная (ложная тревога), но статус «VIOLATED» на точных данных вводит в заблуждение. **Исправление:** то же, что A7(а): отдельный признак «не разрешено». **Как найдено:** проба p6.

### A12 — minor — M_int ≈ M_MS и положительность M не контролируются

Контракт §6: M_int «должна совпадать с M_MS при выполненных связях» — это независимая интегральная проверка, но она не используется ни в одном статусе. ### A14 — note (контракт §9) — входы считаются точными

σ(Rθ±) = 2σ(Γ) учитывает только ошибку численной R′; U = −R K_B считается точным. Для данных из эволюционного кода K_B несёт свою ошибку порядка ошибки схемы; вблизи корня θ± знак «разрешается» с переоценённой уверенностью, а [R_lo, R_hi] занижен. **Предложение:** необязательный вход `sigma_KB` (и `sigma_A`), включаемый в τ±.

### A15 — note — NaN относительной невязки без пометки

Контракт §5: при Σ|T_k| = 0 «не определена (NaN с пометкой)». `_rel` (diagnose.py:493–496) возвращает NaN без флага/счётчика (например 𝓜 в FLRW, где все слагаемые равны 0). **Предложение:** `status['n_rel_undefined'][name]`.

### A16 — note — область `center` при `center="none"`

Нормы `center` берутся по первым max(4, N/20) точкам с R > 0 независимо от типа края; при `center="none"` это внутренняя граница (например экстерьер), где одностороние шаблоны — имя области вводит в заблуждение при сравнении отчётов. **Предложение:** `inner` при `center="none"`.
