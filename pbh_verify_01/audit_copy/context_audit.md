## 4. Выбор модуля

Модуль по умолчанию из §3 ТЗ: **срез (A, R, K^r_r, K^θ_θ) + скалярное поле (φ, Π) → ρ, j_r, S^r_r, S^θ_θ → невязки связей → M_MS → θ± → классификация сфер**. Обоснование: (i) в `pbhgr` такого самостоятельного компонента нет (C9); (ii) он нужен V1b (общие диагностики Code A) и позволяет независимо проверить горизонтный критерий V1 (C3); (iii) он полностью проверяем на точных решениях без EKG-солвера.

Условное расширение (§3 ТЗ): скалярного солвера нет, поэтому эволюцию EKG не пишем. Расширение, если базовые тесты пройдены: (а) однородный FKG-срез из независимого ODE (он же тест матрицы); (б) снимок Vlasov-данных `pbhgr.cosmo_ev` через адаптер вещества — сравнение горизонтного критерия V1 с классификацией модуля. Это проверка интерфейса и C3, а не механизма образования PBH.

## 5. Ресурсы и ограничения среды

- VPS: 2 vCPU, 3.7 ГБ RAM без swap; во время пилота параллельно идут 3D PM-прогоны `pbhgr` (~1.2 ГБ, другой сеанс). Пилот ограничен 1D-вычислениями (< 200 МБ на процесс); существующие процессы и `pbhgr/runs/` не трогаются.
- Python 3.12.3, numpy 2.5.3, scipy 1.18.1, pytest 9.1.1; sympy 1.14.0 установлен локально в `.pydeps/` (для символьной проверки выводов).
- Субагенты доступны (раздельные контексты одной и той же модели). Это даёт организационное разделение ролей, но **не** независимость моделей: совпадение ответов нескольких экземпляров одной модели — не независимое подтверждение физики.
- Прямые денежные расходы: 0 € (серверы и платные API не использовались). Расход токенов субагентов фиксируется в `results/agent_costs.md` по данным среды.
